## 1. 产品定位与用户

### 1.1 是什么

一个自己部署在 VPS 上的 Web 面板，用来**统一管理分散在多个 Oracle Cloud 账号下的云主机**。取代在 Oracle 官方控制台之间反复切换租户、切换区域的痛苦。

**两大功能域**：

| 域 | 内容 |
|---|---|
| **账号管理** | 接入多个 OCI 租户的 API 密钥、校验凭据有效性、管理区域订阅、查看配额与用量、密钥安全托管 |
| **实例管理** | 跨账号聚合的实例列表、开关机与重启、改配置（OCPU/内存）、引导卷扩容与性能调整、公网 IP 与 IPv6、安全规则、流量监控、串行控制台、创建与终止实例 |

### 1.2 用户画像

技术型个人用户。同时持有 **1–20 个 Oracle 账号**，自己搭建、自己运维，对终端和云控制台不陌生。**不是企业运维团队**——不需要审批流、工单、多角色权限矩阵。

### 1.3 三个真实使用场景

| 场景 | 频率 | 设计含义 |
|---|---|---|
| **日常巡检** —— 扫一眼 30 台机器是否都正常 | 最高 | 信息密度要够，一屏看完；异常必须自己跳出来 |
| **定向操作** —— 给某台机器关机 / 扩容 / 换 IP | 中 | 操作路径要短，反馈要即时，危险操作要有门槛 |
| **接入与排障** —— 加新账号，或某个账号突然报错 | 低但关键 | 凭据校验要逐项可见，错误码必须保留原文 |

### 1.4 三个决定设计的洞察

> **① 「这台机器是哪个号的？」是全站最高频的问题。**
> 用户管着 8 个甲骨文号、30 台机器，散落在 6 个区域。跨账号聚合列表的价值全部建立在**能瞬间归属**之上。
> 解法：给每个账号分配一个**稳定的身份色 + 短代号**，在实例表、网络、存储、日志、通知的**每一行**都出现。见 §5.2——这是本产品最重要的一致性机制。

> **② 实例状态转换是一段有时长的过程，不是瞬时事件。**
> 点「关机」到真的 `STOPPED` 要 30–90 秒。UI 必须诚实地表达"正在过渡中"：乐观更新给出即时反馈，同时用过渡态动画表明尚未完成，后台轮询确认后才落定。
> **既不能点完没反应，也不能骗用户说已经好了。** 见 §6.3。

> **③ 这个面板持有你所有甲骨文租户的完整控制权。**
> 一个 API 密钥 = 一个租户的全部权限。这个面板本质是一个**保险箱**。私钥的输入与展示方式、终止操作的门槛、审计日志的可见度——这些不是附加的"安全功能"，是产品的核心界面语言。见 §6.5。

## 2. 设计原则

1. **归属先于一切** —— 任何展示资源的地方，账号身份必须可见。跨账号视图里，一行数据不带账号标识就是残缺的。
2. **状态先于数据** —— 颜色、动效、形状承担主要信息传递。用户应能在 0.5 秒内、不聚焦阅读的情况下判断"有没有出事"。
3. **诚实的过渡态** —— 长耗时操作必须有独立于"完成"和"未开始"的第三种视觉状态。
4. **危险操作显著降权** —— 终止实例、更换 IP、删除账号在视觉上必须"难点到"。见 §6.5 的三级门槛。
5. **暗色是默认** —— 不是主题选项之一。Light 必须完整对等，但设计从 Dark 出发。
6. **等宽即数据** —— OCID、IP、指纹、错误码、时间戳、所有计数器一律等宽。这是这类工具的专业感来源。
7. **抽屉优于跳页** —— 详情用右侧抽屉展开，保留列表上下文。用户在多台机器间比对是高频行为。

```
│  ✎  通知            │  Notifications 推送渠道
│  ⚙  设置            │  Settings      安全 / 审计
├────────────────────┤
│  [ 主题切换 ]       │
│  [ 用户菜单 ]       │
└────────────────────┘
```

- 侧边栏宽 **240px**，可折叠为 **64px** 图标条。
- 「账号」「实例」带数量徽章。
- 活动项指示器：左侧 3px 强调色竖条，切换时磁吸滑动。

### 3.2 顶栏（高 56px，玻璃拟态，吸顶）

```
[面包屑]        [全局搜索 ⌘K]      [账号筛选器 ▾] [区域筛选器 ▾] │ [操作状态] [主题] [头像]
```

**账号筛选器**是全站最重要的顶栏控件。下拉里每个账号前置其身份色点，支持多选（默认全选）。选中后**所有列表页同步过滤**，选择状态跨页面保持。

**操作状态**：有实例正在状态转换（启动/关机/创建/终止）时显示，例如「2 台正在转换」+ 脉冲点；点击展开抽屉查看进度。无事时收起。

### 3.3 全局搜索（⌘K）

跨账号搜索实例名、OCID、IP、账号别名。结果分组显示，每条结果左侧带账号身份色条。这是拥有 30+ 台机器后的主要导航方式。

## 4. 页面设计

### 4.1 登录页

- 全屏深色，背景为动态网格 + 2–3 团缓慢漂移的强调色光晕（60s 周期）。
- 居中玻璃卡片，宽 400px，圆角 xl。
- 两步式：① 用户名 + 密码 ② TOTP（**6 个分格输入框**，自动跳格，粘贴自动分配，填满即自动提交）
- 失败：卡片水平抖动 400ms + 显示剩余尝试次数（`还可尝试 3 次，超出将锁定 15 分钟`）
- 底部极小字号：版本号 + `本面板持有你的 OCI 密钥，请勿暴露在公网`

### 4.2 总览

**① KPI 行**（4 张卡）
```
┌──────────┬──────────┬──────────┬──────────┐
│ 接入账号  │ 实例总数  │ 运行中    │ 本月费用  │
│    8     │    30    │   26     │  $0.00   │
│ 全部正常  │ 6 个区域  │ 4 已停止  │ 免费额度内│
└──────────┴──────────┴──────────┴──────────┘
```
数字用 count-up 滚动，等宽字体，字号 40。

**② 需要注意的**（有内容才显示，无异常时整块隐藏）
一个合并的告警列表：认证失败的账号、异常停止的实例、配额接近上限、引导卷将满、即将到期的保留 IP。每条带账号身份色条 + 直达链接。**这是巡检场景的核心，让异常主动跳出来而不是让用户去找。**

**③ 主区（左 60% / 右 40%）**

左：**实例分布矩阵** —— 行=账号，列=区域，交叉格显示该账号在该区域的实例数（色块深浅表示密度，格子带账号身份色调）。一眼看清资源散布。

右：**配额与用量** —— 每账号一组：ARM OCPU、内存、块存储的使用率条。接近上限转警告色。

**④ 底部** —— 最近操作时间线（跨账号，带身份色条）

### 4.3 账号管理 ★ 核心域一

**卡片网格，不用表格。** 账号数量少（<20），需展示的状态维度多，卡片承载更好。

单卡结构（宽约 340px），**左侧 4px 满高账号身份色条**：
```
┃┌───────────────────────────────────┐
┃│ ● 东京主号              TYO   ⋯  │  状态灯 + 别名 + 短代号 + 菜单
┃│   ocid1.tenancy…7x2k              │  等宽截断，点击复制
┃│                                   │
┃│   [ap-tokyo-1] [ap-osaka-1] +2    │  已订阅区域
┃│                                   │
┃│   实例 6      运行 5      停止 1   │
┃│   ARM 配额 ▰▰▰▰▰▰▰▱▱▱  3/4 OCPU  │
┃│   ─────────────────────────────   │
┃│   ✔ 3 分钟前校验通过               │
┃└───────────────────────────────────┘
```

**状态灯语义**（带呼吸光晕）：

| 颜色 | 含义 | 卡片处理 |
|---|---|---|
| 🟢 绿 | 凭据有效，最近校验通过 | 正常 |
| 🔵 蓝 | 正在校验 | 状态区骨架屏 |
| 🔴 红 | `401 NotAuthenticated` 或 `404 NotAuthorizedOrNotFound` | 整卡降饱和 + 顶部红条 + 一句人话诊断 |
| ⚪ 灰 | 用户手动禁用 | 降透明度 |

#### 4.3.1 添加账号抽屉（右侧，宽 520px）★ 重点

**关键 UX：支持整段粘贴 OCI config 自动解析。** 用户从 Oracle 控制台下载的配置长这样：
```ini
[DEFAULT]
user=ocid1.user.oc1..aaaa…
fingerprint=20:3b:97:13:…
tenancy=ocid1.tenancy.oc1..aaaa…
region=ap-tokyo-1
key_file=/path/to/key.pem
```
提供一个大 textarea，粘贴后自动填充下方所有字段并高亮已识别项。**这一个交互能消除 80% 的配置错误。**

**私钥字段**：多行输入，失焦后立即变为 `••••••••` 并在下方显示 `已加密存储 · 指纹 20:3b:97:…`。**私钥永不回显，界面上无任何导出入口。**

**账号身份**：别名 + 3 字母短代号 + 身份色选择器（8 色，自动分配未被占用的，可手动改）。

**底部实时校验区** —— 点击「测试连接」后逐项亮起：
```
✔ PEM 格式有效
✔ 指纹与私钥匹配
✔ GetUser 调用成功 · user@example.com
✔ 已订阅 4 个区域
⚠ 缺少 instance_family 的 manage 权限，将无法创建实例
```
最后一条是**权限自检**——提前告诉用户哪些功能会不可用，而不是等他点了按钮才报 404。

#### 4.3.2 账号详情抽屉（宽 720px）

Tab 分区：
- **概览** —— 租户信息、用户邮箱、密钥指纹、创建时间、最后校验
- **区域订阅** —— 已订阅区域列表 + 可订阅区域（支持一键订阅新区域）
- **配额** —— 按区域展开：ARM OCPU / 内存 / 块存储 / VCN / 公网 IP 的限额与已用量
- **权限自检** —— 逐项列出本工具需要的 IAM 权限及当前是否具备
- **密钥** —— 指纹展示、轮换密钥入口、禁用账号

### 4.4 实例管理 ★ 核心域二

#### 4.4.1 列表

**表格视图为主，可切卡片视图。默认跨账号聚合。**

| 列 | 说明 |
|---|---|
| ┃ | **左侧 3px 账号身份色条**，满行高。这是归属的第一信号 |
| 状态 | 状态灯 + 文字，见 §6.2 的六种生命周期状态 |
| 名称 | 主文本 + 下方灰色小字显示 OCID 尾 6 位（等宽） |
| 账号 | **AccountChip** —— 身份色圆点 + 三字母短代号（`TYO`） |
| 区域 · AD | `ap-tokyo-1 · AD-1` |
| 规格 | `VM.Standard.A1.Flex` + 下方 `4 OCPU · 24 GB` |
| 公网 IP | 等宽 + 一键复制 + IPv6 折叠展示 |
| 引导卷 | `50 GB · VPU 10`，接近满时转警告色 |
| 运行时长 | `12天 4小时` |
| 操作 | 图标按钮组 + `⋯` 菜单 |

**筛选与分组**：顶部支持按账号、区域、状态、规格筛选；支持"按账号分组"视图（每组一个折叠区，组头带身份色条与小计）。

**批量操作**：行首复选框，选中后浮出操作条（批量开机 / 关机 / 重启）。**批量终止不提供**——太危险，必须逐台执行。

#### 4.4.2 行内操作的安全分级

| 级别 | 操作 | 交互 |
|---|---|---|
| **直接** | 开机、关机、重启（软） | 图标按钮，点击即执行，乐观更新 |
| **确认** | 强制重启、更换公网 IP、分离引导卷 | 弹出确认框，说明后果（`更换后原 IP 不可找回，SSH 连接将中断`） |
| **高门槛** | **终止实例** | 藏在 `⋯` 菜单最底部，红色文字；确认框需**手动输入实例名称**才激活按钮；设置中可全局禁用此功能 |

#### 4.4.3 详情抽屉（宽 720px）

顶部固定：账号身份色条 + 实例名 + 状态徽章 + 主操作按钮组。Tab 分区：

- **概览** —— OCID（可复制）、创建时间、shape、AD、容错域、镜像、cloud-init 元数据、标签
- **网络** —— VNIC 列表、公网/私网 IPv4、IPv6、所属 VCN 与子网、安全规则摘要（可跳转编辑）、更换 IP 入口
- **存储** —— 引导卷（改名 / 扩容 / 调 VPU，带滑块与预估性能）、附加块存储列表
- **监控** —— 流量图（渐变面积 + 流动描边）、CPU、内存，时间范围切换
- **控制台** —— 串行控制台连接、VNC 入口
- **操作记录** —— 本实例的历史操作审计

#### 4.4.4 创建实例向导

右侧抽屉，6 步，顶部步骤条：
```
账号 → 区域·AD → 规格 → 镜像 → 网络 → 初始化
```

- **规格步** —— 提供「免费额度 ARM」快捷预设（A1.Flex 4 OCPU / 24 GB）与「免费 AMD」（E2.1.Micro）。OCPU 与内存滑块**联动**（A1.Flex 每 OCPU 最多 6GB），实时显示该账号剩余配额，超额时禁止下一步。
- **网络步** —— 提供「自动创建 VCN」开关，勾上则无需理解 OCI 网络模型。可选是否分配公网 IP、是否启用 IPv6。
- **初始化步** —— cloud-init 编辑器，等宽 + 语法高亮，提供 SSH 公钥注入模板。
- **确认** —— 完整摘要 + 预估费用（免费额度内显示 `$0.00 · 免费额度内`）

创建后立即在列表中插入一行 `PROVISIONING` 状态的实例，见 §7 Tier 3。

### 4.5 网络

Tab 分区：**VCN** / **子网** / **安全规则** / **公网 IP** / **IPv6**。所有列表跨账号聚合，带身份色条。

- **安全规则**用可视化编辑，不是裸 JSON。每条规则一行：`方向 · 协议 · 源/目标 CIDR · 端口范围 · 描述`。常用端口提供快捷模板（SSH 22 / HTTP 80 / HTTPS 443 / ICMP / ⚠️ 全放行）。全放行规则显示醒目警告标记。
- **公网 IP** 区分「临时」与「保留」。更换操作前明确提示后果。

### 4.6 存储

引导卷与块存储列表，跨账号聚合。支持扩容（只能增不能减，界面须说明）、VPU 性能调整（滑块 + 实时显示预估 IOPS/吞吐）、快照与备份策略。

### 4.7 通知

渠道卡片：Telegram / 企业微信 / 钉钉 / 邮件 / 自定义 Webhook。每张卡有开关、配置表单、**发送测试**按钮（立即反馈成功/失败）。

事件订阅矩阵（行=事件，列=渠道）：
```
                      TG   企微  邮件
实例状态异常变化      ☑    ☑    ☑
账号认证失败          ☑    ☐    ☑
配额接近上限          ☑    ☐    ☐
引导卷空间告警        ☑    ☐    ☐
实例创建完成          ☑    ☑    ☐
```

### 4.8 设置

分区：**账户安全**（改密 / TOTP 绑定与二维码 / 会话管理与强制下线）· **操作策略**（是否允许终止实例 / 是否允许批量操作 / 危险操作是否需重新验证 TOTP）· **外观**（主题 / 强调色 / 密度 / 动效开关）· **审计日志**（可筛选表格：时间 / 操作者 / 动作 / 目标账号 / 目标资源 / 来源 IP / 结果）· **关于**

## 5. 设计令牌

> 请在 Figma 中建成 **Variables**（Color / Number / String 三类集合），配置 Light / Dark 两个 Mode。组件必须绑定变量，禁止硬编码色值。

### 5.1 中性色（Dark 为默认 Mode）

| Token | Dark | Light | 用途 |
|---|---|---|---|
| `bg-base` | `#0A0B0F` | `#F7F8FA` | 页面底色 |
| `bg-surface` | `#12141A` | `#FFFFFF` | 卡片、表格 |
| `bg-elevated` | `#1A1D26` | `#FFFFFF` | 抽屉、弹窗、下拉 |
| `bg-inset` | `#08090C` | `#EDEFF3` | 代码块、日志区、输入框 |

### 5.2 账号身份色 ★ 本产品的核心机制

**问题**：用户管着最多 20 个账号、上百个资源，散落在多个区域。跨账号聚合列表的全部价值建立在"能瞬间归属"之上。

**解法**：每个账号在接入时分配一个**稳定的身份色 + 三字母短代号**，二者绑定后不再变化，并在**每一处出现该账号资源的地方**同时呈现——实例表左侧色条、AccountChip、网络与存储列表、日志行、通知消息、搜索结果。

## 6. 核心组件

### 6.1 AccountChip —— 全站最高频组件

账号身份的最小可见单元。出现在每一处引用账号的地方。

```
● TYO        ← 身份色圆点 6px + 三字母短代号（等宽，600 字重）
```

变体：
- `dot`（仅色点，用于极窄空间）
- `chip`（色点 + 代号，**默认**）
- `full`（色点 + 代号 + 完整别名，用于抽屉标题与下拉选项）
- 状态叠加：账号异常时代号旁加 `⚠` 并转 danger 色

hover 显示 tooltip：完整别名 + 租户 OCID 尾 6 位 + 当前连通状态。

### 6.2 StateBadge —— 实例生命周期六态

| 状态 | 色 | 灯 | 文案 | 动效 |
|---|---|---|---|---|
| `RUNNING` | success | 实心 | 运行中 | 静止 |
| `STOPPED` | neutral | 空心 | 已停止 | 静止 |
| `PROVISIONING` | info | 实心 | 创建中 | **脉冲 + 进度条** |
| `STARTING` | transition | 实心 | 启动中 | **脉冲** |
| `STOPPING` | transition | 实心 | 关机中 | **脉冲** |
| `TERMINATING` | warning | 实心 | 终止中 | **脉冲**，整行降透明 |

`TERMINATED` 的实例默认从列表隐藏，可通过筛选器显示，显示时整行划除 + 60% 透明。

**关键规则**：**只有过渡态（PROVISIONING / STARTING / STOPPING / TERMINATING）带动画**。RUNNING 和 STOPPED 是稳定态，必须完全静止——否则动效就失去了"有事在发生"的语义。

### 6.3 LifecycleTransition —— 诚实的过渡态 ★

用户点击「关机」后的完整时间线：

```
t=0      按钮进入 loading（图标转为 spinner），行内状态立刻变为「关机中」+ 脉冲
         ↑ 乐观更新：立即给反馈，但用过渡态而非终态
t=0.4s   API 返回 202，按钮 loading 结束，行内出现细进度条（indeterminate）
t=0~90s  后台轮询 GetInstance，进度条持续
t=完成    状态跃迁为「已停止」，ease-spring 弹性过渡，行短暂高亮一次后回落
t=失败    状态回滚为原状态，行内浮出错误提示条（含原始错误码 + 重试按钮）
```

**三条硬规则**：
1. 乐观更新只能更新到**过渡态**，绝不能直接跳到终态。
2. 过渡期间该行的所有操作按钮禁用（避免重复提交）。
3. 失败必须**可见地回滚**，不能静默恢复。

### 6.4 InstanceRow —— 列表主体

```
┃ ● 运行中  arm-tokyo-01        ●TYO  ap-tokyo-1·AD-1  A1.Flex          152.70.x.x   50GB   12天4h   [▶][⏸][↻][⋯]
┃           ocid1…a7x2k                                4 OCPU · 24 GB    VPU 10
```

- 选中：行左侧 accent 竖条 + `accent-soft` 背景
- 状态异常（如意外 STOPPED）：状态列徽章加 `⚠`

### 6.5 危险操作的三级门槛 ★

| 级别 | 适用 | 交互 |
|---|---|---|
| **L1 直接** | 开机 / 软关机 / 软重启 | 图标按钮直接执行 |
| **L2 确认** | 强制重启 / 更换公网 IP / 分离引导卷 / 禁用账号 | 弹出确认框：**标题说明将发生什么** + 后果描述 + 取消（主）/ 确认（次，warning 色） |
| **L3 输名确认** | **终止实例** / **删除账号** | 红色确认框；列出将丢失的内容（实例名、引导卷、IP、数据）；**必须手动输入资源全名**才激活确认按钮；按钮为 danger 实色 |

**L3 确认框的文案要求**：不写「此操作不可撤销，确定吗？」，写**具体丢失什么**：
```
终止实例 arm-tokyo-01

以下内容将被永久删除，无法恢复：
· 实例本身及其全部系统数据
· 引导卷 arm-tokyo-01-boot（50 GB）
· 临时公网 IP 152.70.x.x

请输入实例名称以确认：
[                    ]
[ 取消 ]  [ 永久终止 ]  ← 输入匹配前禁用
```

设置中可**全局禁用终止功能**，禁用后该菜单项灰显并提示「已在设置中禁用」。

## 7. 特效清单

按"是否承载信息"分三级。**Tier 1 必做，Tier 2 推荐，Tier 3 点睛。**

### Tier 1 — 承载信息（必做）

1. **过渡态脉冲 `transition-pulse`** —— 状态灯 + 外扩光环，2s 周期。**仅用于四种过渡态**，稳定态绝对静止。这是"有事在发生"的唯一信号。
2. **不定进度条 `indeterminate-bar`** —— 2px 细条，在行底或卡片底横向往复。用于状态转换与创建中。
3. **状态跃迁弹性过渡** —— 状态徽章从过渡态变为终态时，`ease-spring` 轻微缩放回弹（240ms）+ 整行高亮一次后回落（600ms）。**这是操作完成的确认信号。**
4. **按钮乐观反馈** —— 点击 → spinner（160ms 内出现）→ 成功勾（480ms）→ 回落。失败则抖动 + 转 danger。
5. **数字 count-up** —— KPI 变化时滚动 600ms `ease-decelerate`。等宽字体保证不抖动。
6. **骨架屏 shimmer** —— 45° 高光条 1.4s 循环。所有列表/卡片首次加载必须有，**禁止用居中转圈代替**。
7. **账号色条 hover 提亮** —— 行 hover 时左侧身份色条亮度 +20%，强化归属感知。

### Tier 2 — 提升质感（推荐）

8. **玻璃拟态** —— `backdrop-filter: blur(20px) saturate(160%)` + 半透明底 + 1px 高光内边框。顶栏、抽屉、弹窗、下拉。
9. **鼠标跟随光斑** —— 卡片 hover 时 400px 径向渐变（`accent` 8%）跟随指针，CSS 变量传坐标。
10. **背景网格 + 漂移光晕** —— 仅登录页与总览页。1px 网格 + 2–3 团 600px 光晕，60s 周期漂移。
11. **侧边栏磁吸指示器** —— 活动竖条在导航项间滑动，`ease-spring` 320ms。
12. **抽屉滑入** —— 从右侧 `ease-decelerate` 240ms 滑入 + 遮罩淡入。
13. **图表渐变流动** —— 流量面积图用 `accent` 到透明的垂直渐变；折线描边叠一层缓慢流动高光。
14. **分组折叠** —— 按账号分组视图展开/收起时高度过渡 240ms，组内行错峰 20ms 淡入（**总时长不超过 300ms**）。

### Tier 3 — 高光时刻（点睛）

15. ★ **实例就绪 `instance-ready`** —— 本产品唯一值得铺张的时刻：新建实例从 `PROVISIONING` 变为 `RUNNING`。
    - 该行从左至右扫过一道 `success` 色高光（600ms `ease-decelerate`）
    - 状态徽章 `ease-spring` 弹性放大回弹
    - 公网 IP 字段以 count-in 方式逐段浮现（这是用户真正在等的东西）
    - 右下角 toast：`arm-tokyo-01 已就绪 · 152.70.x.x`，附一键复制 SSH 命令
    - **全程不超过 1.2s，不阻塞任何操作**
16. **页面切换 View Transition** —— 内容区交叉淡入 + 4px 上移，240ms。

### 明确不要做的

- ❌ 稳定态（RUNNING / STOPPED）上的任何循环动画——会摧毁过渡态的语义
- ❌ 列表项逐个弹跳入场
- ❌ 视差滚动
- ❌ 彩色投影滥用（光晕只在 §5.7 定义的三处用）
- ❌ 超过 700ms 的常规过渡（`instance-ready` 是唯一例外）
- ❌ 用动效表达"装饰"而非"状态"

### 性能红线（硬约束）

- 动画属性**只用** `transform` 和 `opacity`。禁止动画 `width` / `height` / `top` / `left`。
- 同屏 `backdrop-filter` **≤ 3 层**。
- 一屏 100 行的实例表，**同时脉冲的过渡态行 ≤ 12 个**，超出的用静态徽章 + 计数汇总。
- **`prefers-reduced-motion: reduce` 必须全量降级**：循环动画停止，过渡时长归零，仅保留颜色变化。设置中另提供独立的「减弱动效」开关。
- 后台标签页暂停所有循环动画与轮询。

而且没有任何宽度检测或跳转，手机上打开看到的其实是桌面表格——那两个
移动页面谁也走不到。

半成品比没有更糟：它让人以为移动端是可用的。要么按上面那份规格补完
（卡片列表、全屏详情、≥44px 触控目标、L3 门槛不简化），要么就不留。
目前选择不留。

## 10. 状态设计与可访问性

### 10.1 四态

| 态 | 要求 |
|---|---|
| **加载** | 骨架屏，形状贴合真实内容。**禁止用居中转圈代替。** |
| **空** | 图标 + 一句话说明 + 明确的主行动按钮。文案要具体 |
| **错误** | 人话描述 + **保留原始错误码**（等宽、可复制——用户要拿去搜）+ 重试按钮 |
| **无权限** | 说明缺少哪个 IAM 权限 + 如何在 Oracle 控制台添加 |

**关键空态文案**（请直接用）：
- 账号页：`还没有接入任何 Oracle 账号` / `接入后即可统一管理所有实例` + `[ 添加第一个账号 ]`
- 实例页（无账号）：`先接入一个 Oracle 账号` / `实例列表会自动同步` + `[ 去添加账号 ]`
- 实例页（有账号无实例）：`该账号下暂无实例` + `[ 创建实例 ]`
- 筛选无结果：`没有符合筛选条件的实例` + `[ 清除筛选 ]`
- 网络页：`该账号尚未创建 VCN` / `创建实例时可以自动创建`

### 10.2 可访问性下限

- 正文对比度 **≥ 4.5:1**，大字号与图形 **≥ 3:1**。Dark 主题的 `text-tertiary` 与八色账号色板请**逐一实测**。
- **颜色绝不是唯一信息载体**：
  - 账号身份色**必须**与三字母短代号同时出现
  - 实例状态**必须**有文字标签，不能只靠灯的颜色
  - 状态灯用**实心/空心**区分稳定态与已停止，形成第二重编码
- 所有交互元素有清晰 focus ring（2px `accent` + 2px offset），键盘可完整操作。
- 抽屉/弹窗焦点陷阱 + `Esc` 关闭。**L3 确认框的确认按钮不得是默认焦点。**
- 状态变化用 `aria-live="polite"` 播报（如「arm-tokyo-01 已停止」）。
- 尊重 `prefers-reduced-motion` 与 `prefers-color-scheme`。

## 12. 不在本期范围

以下功能**本期不做设计**，但架构上预留位置，未来可作为一级导航项插入「实例」之后：

- 费用与账单分析
- 多用户与 RBAC
- 实例迁移与镜像导出

设计时请**不要**为这些功能预留视觉元素或占位入口——留白比占位更容易扩展。

## 13. 一句话概括视觉方向

**深色终端质感的多账号控制台**：八种身份色让三十台机器各归其位，大量等宽数字，动效只用来说明"有事正在发生"。冷静、精密、克制——把炫技的预算全部花在让用户不点错那个按钮上。
